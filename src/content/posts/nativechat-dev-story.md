事情的起点很具体：网页版的聊天用得还算顺手，但它在手机上不对劲。输入框会跳、切后台就重载、附件传一半断掉就没了。

于是我想把它搬到安卓上。不是套个 WebView，而是真的原生。

## 第一道坑：这台机器根本编不出安卓 App

最开始我以为装个 Gradle 就完事了。结果发现构建环境是这样的：

- 安卓手机里的 proot Ubuntu 24.04，arm64，没有 root
- 能装 JDK 17、`aapt`、`d8.jar`、`apksigner.jar`
- 但 Gradle 和 AGP 跑不起来

原因很硬：AGP 依赖的 `aapt2` 只有 x86_64 产物。翻了 Google Maven 上六百多个版本，没有一个 arm64 的可执行文件。Kotlin + Jetpack Compose 这套官方路线，在这台机器上直接堵死。

那就自己做构建链：

```
aapt 编资源 → javac → d8 → 手写打包（pack.py） → apksigner
```

打包那一步最难。`pack.py` 要自己拼 manifest 和 `resources.arsc`，还得保证 4 字节对齐，否则装不上。就这样把第一个能装的包弄出来了。

## 第二道坑：协议根本不是我以为的那个

第一版发消息直接 HTTP 400。我一开始按 OpenAI 的写法对接：`POST /chat/completions`，图片用 `image_url`。全错。

回去读网页版的源码才发现，它用的是 **Anthropic 兼容接口**：

```
POST {origin}/anthropic/v1/messages
header: x-api-key
```

请求体也不一样：`thinking`、`safety_check`、`tools`、首轮还要带 `title`，全部 `stream: true`。

流式事件得按它的名字一个个认：

| 事件 | 干什么 |
|---|---|
| `message_start` | 初始化回答，带 model 和 usage |
| `content_block_start` | 块的类型：正文、思考、联网搜索、工具调用 |
| `content_block_delta` | 增量，正文与思考各走各的 |
| `message_delta` | 结束原因、用量，**还有服务端生成的会话标题** |
| `message_stop` | 正常结束 |

错误也要分五类，不然后面没法定位：`http`、`stream`、`network`、`interrupted`、`protocol`。其中 `interrupted` 最坑——没收到 `message_stop` 就断开，已经收到的内容要留着当「已停止」，不能当失败丢掉。

## 移植的是逻辑，不是界面

我给自己定的规矩是「语义等价」，不是把界面抄一遍。所以真正在写的是这些东西：

- **状态机**：`pending / streaming / done / stopped / error`
- **消息分支**：每条消息带 `parentId` 和 `selectedChildId`，重新生成不会覆盖旧版本，而是开一个分支，界面上显示成 `1/2`
- **上下文构建**：只有「已完成或已停止、有正文、没被拒绝」的回复才进上下文；助手历史只回传正文和联网工具块，思考内容不回传
- **续写**：末尾可续写的消息作为 assistant 前缀发出去

这套规则看着琐碎，但它决定了多轮对话到底靠不靠谱。

## 附件：会过期的 file_id

附件不是简单地把图片塞进请求体。路径是：

1. 本地先存原件
2. 发送前 `POST /anthropic/v1/files` 换一个 `file_id`
3. 消息里用块引用这个 id
4. 服务端说过期了 → 重新上传再重发，**最多两次**，退避 `2^n` 秒

第二次失败之后就得报错，不能无限重试。

## 数据怎么带走

这部分我花的时间比界面多。

导出是一个 ZIP（v3）：`manifest.json` → `chat_sessions/*.json` → `chat_session_index.json` → 图片原件。

导入不能直接写库。流程必须走完：先校验 manifest 和版本，写进暂存区，全量校验，最后**单事务原子替换**。中途崩了也不会留下半截数据。

代价是导入会整体覆盖本机现有对话——这也是我在下载页上把那句提醒标红色的原因。

还有个真实的性能坑：大包导入会卡死。原因是逐条读 ZIP 目录项，一次大包要读八千多次。改成中央目录一次读完 + 1 MB 顺序预读缓冲，读取次数降到两百多，瞬间就快了。

| 版本 | 加了什么 |
|---|---|
| 1.4 | 基础版，先能聊 |
| 1.4.5 | 拍照入口，附件改成相机 / 相册 / 文件的底部抽屉 |
| 1.4.7 | 消息里能显示图片缩略图和文档卡片 |
| 2.0.0 | 按需上下文、多模型配置档案、用量与价格、长图分片、应用内更新日志 |
| 2.1.0-beta5 | 图片附上简短的可见内容描述请求 |

中间还有三十多个测试构建，命名为 `ChatNative-ui.apk`、`ChatNative-sync-check.apk` 这种，都没往外发。

## 哪些事它现在做不好

写到这里得说清楚，免得给人错误期待：

- **云同步不是永久实时保障。** 后台只在进程还活着的时候尝试继续，系统杀进程、强制停止、退出应用都会中断，得重新打开看结果。
- **停用的摘要不会自动恢复。** 原消息不删，但受上下文预算裁剪和历史图片省略影响，不保证全部回传。
- **导入会覆盖本机数据**，而且不能撤回。
- **大历史压缩会被拒绝。** 长历史或附件塞不进摘要时，会直接拒绝而不是假装成功。

## 最后

这个东西现在还是个 Beta。它不完美，但它确实做到了一件事：把网页版里那套协议、流式、分支、附件的逻辑，真实地跑在了安卓原生上，而没有套一层浏览器。

下一个版本想先把同步的边界条件收敛好，再谈别的。
